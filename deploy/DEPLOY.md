# Выкладка на сервер

Итог: `https://<твой-домен>` (например saydarai.app) открывается из любого Chrome/Edge, HTTPS настраивается сам (Caddy + Let's Encrypt).
Звук по-прежнему захватывается в браузере на твоём компьютере — сервер только распознаёт и отвечает.

## 1. Домен
Самые выгодные рабочие варианты (цены за год, октябрь 2026):
| Зона | Регистрация | Продление | Где дешевле | Заметки |
|---|---|---|---|---|
| **.app** | ~$8 | ~$14 | Cloudflare / Porkbun | лучший вариант для веб-приложения: HTTPS обязателен (у нас и так есть), чистая репутация |
| **.com** | ~$10.5 | ~$10.5 | Cloudflare | самый привычный, продление не дорожает |
| .xyz | ~$2 | ~$14 | Porkbun | дёшево только первый год; корпоративные фильтры иногда режут такие зоны |
| .ai | ~$80 | ~$80 | Porkbun / Cloudflare | минимум 2 года (~$160) |
Бесплатно для теста: поддомен `имя.duckdns.org` (duckdns.org) — указываешь IP сервера, HTTPS работает так же.
Если нужен «ai» в имени дёшево — пусть он будет частью слова: `saydarai.com`, `getsaydar.app`.

## 2. Сервер (VPS)
- Любой Ubuntu 24.04 с 1–2 vCPU / 2 GB RAM: Hetzner, DigitalOcean, Vultr и т.п. (порядка $5–7/мес).
- Регион — Европа (Германия/Финляндия/Нидерланды): близко к тебе и к API Deepgram/Anthropic.
- При создании добавь свой SSH-ключ (`cat ~/.ssh/id_ed25519.pub`; если нет — `ssh-keygen -t ed25519`).

## 3. DNS
У регистратора домена создай записи:
| Тип | Имя | Значение |
|---|---|---|
| A | `@` | IP сервера |
| A | `www` | IP сервера |

В Cloudflare у обеих записей переключи облачко в серое «DNS only» — сертификат выпустит сам сервер (Caddy).

## 4. Подготовить сервер (один раз)
```bash
cd ~/meeting-copilot
ssh root@IP_СЕРВЕРА 'bash -s' < deploy/server-setup.sh
```

## 5. Выложить
В `.env` добавь строку `DOMAIN=твой-домен.ai` (APP_TOKEN уже есть). Затем:
```bash
./deploy/push.sh root@IP_СЕРВЕРА              # код, ключи, context/
./deploy/push.sh root@IP_СЕРВЕРА --with-data  # + твои сохранённые чаты и «Обо мне» (data/)
```
Скрипт напечатает ссылку вида `https://твой-домен/?token=…` — открой её один раз, дальше сайт помнит вход.

Если в `desktop/dist` есть собранные приложения (`npm run dist:mac` / `dist:win`), `push.sh` выложит их на
публичную страницу `https://твой-домен/download` — там кнопка «Скачать» под систему посетителя и инструкция.
Сами установщики паролей не содержат; ссылку с токеном человек вставляет в приложение при первом запуске
(на странице скачивания владелец видит кнопку «Скопировать ссылку», если уже открывал копилот в этом браузере).

## Обновить после изменений
Тот же `./deploy/push.sh root@IP_СЕРВЕРА` — перезальёт код и перезапустит контейнер (данные на сервере сохраняются).

## Полезное
```bash
ssh root@IP 'cd /opt/copilot && docker compose logs -f app'   # логи
ssh root@IP 'cd /opt/copilot && docker compose restart app'   # перезапуск
```
Важно: пароль (APP_TOKEN) — единственная защита до появления аккаунтов. Не публикуй ссылку с `?token=`;
если она утекла — поменяй APP_TOKEN в `.env` и снова `push.sh`.
